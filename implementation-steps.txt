## Step 1: Create the EKS Cluster

Create an EKS cluster using either `eksctl` or Terraform.

Use the following placeholders throughout the deployment:

```bash
<EKS_CLUSTER_NAME>
<AWS_ACCOUNT_ID>
<AWS_REGION>
```

Example region:

```bash
<AWS_REGION>=ap-south-1
```

---

## Step 2: Configure GitHub OIDC and EKS Access

Pick the GitHub repository's immutable URL and add it to the AWS IAM role trust policy for OIDC.

Then add the same IAM role to the EKS cluster access entries.

---

## Step 3: Add GitHub Repository Secrets

Add the required secrets to the GitHub repository:

* `AWS_ACCOUNT_ID`
* `AWS_ROLE_ARN`
* `EKS_CLUSTER_NAME`
* `SONAR_TOKEN`

Make sure SonarCloud has access to the GitHub repository through the required GitHub application/integration.

---

## Step 4: Authenticate Docker with Amazon ECR

Replace the placeholders with your AWS account ID and region:

```bash
aws ecr get-login-password --region <AWS_REGION> | \
docker login --username AWS --password-stdin \
<AWS_ACCOUNT_ID>.dkr.ecr.<AWS_REGION>.amazonaws.com
```

## Step 5: Build and Push Images to Amazon ECR

The application contains five services:

* frontend
* user-service
* task-service
* notification-service
* analytics-service

### Create ECR repositories

```bash
aws ecr create-repository \
  --repository-name task-management/frontend \
  --region <AWS_REGION>

aws ecr create-repository \
  --repository-name task-management/user-service \
  --region <AWS_REGION>

aws ecr create-repository \
  --repository-name task-management/task-service \
  --region <AWS_REGION>

aws ecr create-repository \
  --repository-name task-management/notification-service \
  --region <AWS_REGION>

aws ecr create-repository \
  --repository-name task-management/analytics-service \
  --region <AWS_REGION>
```

### Set environment variables

```bash
export ACCOUNT_ID=<AWS_ACCOUNT_ID>
export REGION=<AWS_REGION>
export REGISTRY=$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com
```

### Build and push the images

```bash
docker buildx build \
  --platform linux/amd64 \
  --push \
  -t $REGISTRY/task-management/frontend:latest \
  ./frontend

docker buildx build \
  --platform linux/amd64 \
  --push \
  -t $REGISTRY/task-management/user-service:latest \
  ./user-service

docker buildx build \
  --platform linux/amd64 \
  --push \
  -t $REGISTRY/task-management/task-service:latest \
  ./task-service

docker buildx build \
  --platform linux/amd64 \
  --push \
  -t $REGISTRY/task-management/notification-service:latest \
  ./notification-service

docker buildx build \
  --platform linux/amd64 \
  --push \
  -t $REGISTRY/task-management/analytics-service:latest \
  ./analytics-service
```

## Step 6: Deploy the AWS Load Balancer Controller

### 6.1 Create the IAM Policy

Use the shared `iam_policy.json` file:

```bash
aws iam create-policy \
  --policy-name AWSLoadBalancerControllerIAMPolicy \
  --policy-document file://iam_policy.json
```

The policy ARN will be:

```text
arn:aws:iam::<AWS_ACCOUNT_ID>:policy/AWSLoadBalancerControllerIAMPolicy
```

### 6.2 Create the IAM Service Account

```bash
eksctl create iamserviceaccount \
  --cluster=<EKS_CLUSTER_NAME> \
  --namespace=kube-system \
  --name=aws-load-balancer-controller \
  --attach-policy-arn=arn:aws:iam::<AWS_ACCOUNT_ID>:policy/AWSLoadBalancerControllerIAMPolicy \
  --override-existing-serviceaccounts \
  --region=<AWS_REGION> \
  --approve
```

Check the service account:

```bash
kubectl get sa -n kube-system
```

```bash
kubectl describe sa aws-load-balancer-controller -n kube-system
```

### 6.3 Add the Helm Repository

```bash
helm repo add eks https://aws.github.io/eks-charts
helm repo update
```

### 6.4 Install the AWS Load Balancer Controller

```bash
helm install aws-load-balancer-controller \
  eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=<EKS_CLUSTER_NAME> \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller
```

## Step 7: Create IAM Role for the Notification Service

The notification service needs permission to use Amazon SES to send email alerts.

### 7.1 Create the namespace

```bash
kubectl create namespace task-management
```

### 7.2 Create the service account

```bash
eksctl create iamserviceaccount \
  --cluster=<EKS_CLUSTER_NAME> \
  --namespace=task-management \
  --name=notification-service-sa \
  --attach-policy-arn=arn:aws:iam::aws:policy/AmazonSESFullAccess \
  --override-existing-serviceaccounts \
  --region=<AWS_REGION> \
  --approve
```

Check the service account:

```bash
kubectl describe sa notification-service-sa -n task-management
```

The output should contain an IAM role annotation similar to:

```text
eks.amazonaws.com/role-arn: arn:aws:iam::<AWS_ACCOUNT_ID>:role/<IAM_ROLE_NAME>
```

### 7.3 Configure Amazon SES

If Amazon SES is running in sandbox mode, verify at least two email identities:

* Sender email
* Receiver email

Use the verified addresses in the task management application.

### 7.4 Update the Notification Service

Update the notification service manifest with the verified sender email address.
